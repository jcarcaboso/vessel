Vessel 0.1.2 gives the app a new look, adds an allocation view to Overview and
lets evidence images live in S3-compatible storage. It needs no database
migration.

## Highlights

### A calmer, more crafted interface

- A readable type scale (nothing below 11px), a signature accent in every theme,
  panels lit from above, a new hull-and-waterline mark and a quiet depth-contour
  texture. Section positions are unchanged.
- Graphite's accent is now cornflower (`#9ab5f2`). Reset it in Settings ›
  Customize colours if you prefer the old steel blue.
- Much less helper text. Notes that matter appear as pills, info tips on the
  thing they explain, coverage badges only when data is incomplete, or one
  "About these numbers" disclosure. Required warnings stay visible.
- Every dropdown shares one style.

### Overview allocation

- Donuts show each portfolio's share of the total and each account's share of
  its portfolio, following the Overview scope.
- Click a slice to focus it. Click it again, use the back arrow or press
  **View all** to return to All accounts.

### Plays

- The journal has one header row, more room by default and an **Expand journal**
  view over the same live notes.
- The Review tab appears once a Play is Open, Closed or Cancelled.
- A Play saved without a name is titled `<asset> <Direction> · <date>`, for
  example `BTC Long · 15 Oct 2026`.
- Play lists show the asset, venue and account as three distinct pieces.

### Accounts

- Group accounts by venue or by owner address, alongside the existing filters.

### Evidence storage

- Evidence images can be kept in any S3-compatible service. The Compose example
  now starts a private RustFS by default.
- An API without storage settings keeps using its local folder. Bad S3 settings
  or an outage never fall back to local files.
- New offline commands, `evidence-copy-to-s3` and `evidence-copy-to-local`, copy
  and verify every original (size and SHA-256). They dry-run by default and
  never delete originals or change configuration.

### Deployment

- A first-time Compose start no longer fails now and then at the migration
  step. The PostgreSQL health check now waits for the real database server.
- Releases are now published automatically from a version tag, with these notes
  as the GitHub Release.

## Upgrading from 0.1.1

1. Back up the database, evidence and credential key ring.
2. **Keeping images in a local folder?** If you take the new `compose.yaml`, add
   `-f compose.storage-local.yaml` to every Compose command. Without it, the
   stack switches to RustFS, where your existing images are not present. To
   move them to S3 instead, follow
   [Copy existing local images to S3](https://github.com/jcarcaboso/vessel/blob/v0.1.2/deploy/README.md#copy-existing-local-images-to-s3).
3. Set `VESSEL_VERSION=0.1.2` and follow the usual
   [upgrade procedure](https://github.com/jcarcaboso/vessel/blob/v0.1.2/deploy/README.md#upgrade-procedure). There is no
   new migration.

## Images

Linux amd64, in [`skorcius/vessel`](https://hub.docker.com/r/skorcius/vessel):

- `skorcius/vessel:api-0.1.2`
- `skorcius/vessel:web-0.1.2`

`api-latest` and `web-latest` point to these images. Deploy the fixed versions
for predictable upgrades.

## Known limits

- Lighter and manual accounts store no owner address, so grouping by address
  lists them together in one group without an address.
- Fields in a locked plan and some indicator legend colours are below 4.5:1
  contrast in light themes.
