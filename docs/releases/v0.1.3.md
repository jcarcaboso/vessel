Vessel 0.1.3 keeps Activity and the Plays list fast as your history grows. Both
now load a page at a time from the server. It includes one database migration.

## Highlights

### Activity

- Operations come in numbered pages with a **Rows per page** selector of 25, 50
  or 100 (25 by default).
- Filters now run on the server. Totals, results and coverage notes still cover
  every retained fill, so the numbers are unchanged.
- An operation's executions load when you expand it. The old limits of 500
  operations and 10,000 execution rows are gone.
- If new fills arrive while you are on a later page, an **Activity changed**
  notice offers a reload.
- Account detail pages its operations the same way.

### Plays

- New tabs with counts: **Drafts**, **In progress**, **Needs review**,
  **Reviewed**, **Closed**, **Cancelled** and **All**. Drafts now have their own
  tab, and Closed and Cancelled are separate.
- Search Plays by title or instrument. The tab counts follow the search.
- Drafts and In progress show every Play. The other tabs use the same pager as
  Activity.
- Your tab, search and page are kept when you open a Play and come back.
- The list loads faster because it no longer reads each Play's plan, drawings
  and review text.

### Overview

- The Plays panel adds a Drafts tab and shows the five most recent Plays in each
  tab. **View all** opens the Plays page on the same tab.
- Plays and recent operations load only the rows Overview shows.

### Loading

- While a list loads for the first time, a skeleton shaped like its rows
  appears. It shows only when loading takes longer than a moment, and it doesn't
  animate when your system asks for reduced motion.
- When you change page or filter, the current rows stay visible but dimmed
  until the new ones arrive.

## Upgrading from 0.1.2

This release adds migration `20261016104756_PlayDirection`.

1. Back up the database, evidence and credential key ring.
2. Set `VESSEL_VERSION=0.1.3` and follow the
   [upgrade procedure](https://github.com/jcarcaboso/vessel/blob/v0.1.3/deploy/README.md#upgrade-procedure).
   Keep web and API stopped while the migration service runs.
3. After the migration, older API images can no longer save Plays. To go back,
   restore the backup rather than starting an older image.

Storage, credentials and Compose files are unchanged.

## Images

Linux amd64, in [`skorcius/vessel`](https://hub.docker.com/r/skorcius/vessel):

- `skorcius/vessel:api-0.1.3`
- `skorcius/vessel:web-0.1.3`

`api-latest` and `web-latest` point to these images. Deploy the fixed versions
for predictable upgrades.

## Known limits

- Activity still works out every operation from all retained fills on each
  request, then returns one page. Very long histories make each page request as
  slow as the full calculation.
- On a desktop Overview, the Plays tabs wrap onto two lines.
- Lighter and manual accounts store no owner address, so grouping by address
  lists them together in one group without an address.
- Fields in a locked plan and some indicator legend colours are below 4.5:1
  contrast in light themes.
