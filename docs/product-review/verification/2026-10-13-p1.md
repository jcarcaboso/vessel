## Independent adversarial reviews

Two Sol agents reviewed the integrated diff independently. Neither was an
implementation worker. They reported five actionable findings:

| Finding | Fix and regression |
| --- | --- |
| A1: 100 ns timestamps truncate in PostgreSQL and poison later ledger/Review reads | Reject sub-microsecond execution timestamps before mutation on create and correction. Real-PostgreSQL regression failed before the fix and passes after it, including fresh-host ledger, history, Review and exclusion reads. |
| A2: ledger reload advances the version without the saved review fields | Adopt returned document fields and version together when clean. Preserve dirty edits and their original version when saved fields differ, with a reconciliation warning. The same guard covers venue/lifecycle responses. |
| B1: idempotent replay replaces a newer displayed manual ledger | Older read/replay responses cannot downgrade visible records, history or totals. Frozen retry payload and request ID remain unchanged. Rechecks exposed remount/failed-GET and dirty-review-baseline variants. The session now retains the latest observed version separately from the editable baseline, scoped to the API, Play and account. An older successful replay acknowledges the write but cannot show stale totals or clear an unresolved saved-document conflict. |
| B2: discard during save lets the late response attach a saved ID to an empty draft | Disable and guard destructive discard while a mutation is pending. A synchronous shared guard spans save, lifecycle, delete, manual writes and loading, with operation-specific cleanup. Save-then-plan retains the guard across both steps. Rechecks exposed shell navigation destroying the guard and Overview New play replacing a draft whose edits had been reverted during Save. The shell now retains its mutation owner while hiding the Plays UI and stopping execution polling. Overview checks the same synchronous guard before replacing a session. Disconnect and API replacement invalidate the old owner. Frozen retry identity survives navigation, and other writes or discard cannot bypass pending work. |
| B3: retrospective links say Removed entry / Unplanned exit | Use Actual entry / Actual exit and owner-confirmed retrospective provenance, with no invented plan or automatic-matching claim. Verified in both component tests and the browser. |

Frontend component regressions cover these fixes and related
concurrency cases, including remount/API replacement, failed GET and stale

## Deliberate limits

- Manual ledger assumes linear USD-quoted contracts and one base unit per
  quantity. Unsupported currencies/multipliers are not inferred.
- Unknown costs stay unknown. Only supported execution fees are included;
  no funding or slippage importer is added. Manual facts do not change
  reported balances or appear as venue imports in Activity.
- Manual ledger rejects further writes after 200 records or 1,000 history
  revisions. Reason lists cap at 100 with an explicit omitted-count reason.
- Retrospective creation supports complete, unassigned, whole-order round
  trips only. Split/flip/ambiguous/partial/already-linked history is rejected.
  Retrospective Plays do not enter the sizing ladder.
- Existing inconsistent records are diagnosed, not silently repaired.
- Existing sync HTTP-under-transaction behavior remains. New diary paths make
  no venue HTTP calls; changing sync management semantics is separate work.
- This is an unmerged delivery, not a release or production deployment.
  The owner's database still requires an explicitly authorized migration.
